# Project Tiny Plot (рабочее название) — статус и план

## Контекст: пивот концепции

Существующий код в проекте — рабочий MVP «SIDE QUEST» (геймифицированный квест-трекер: квесты, XP-язык, коллекции как прогресс-бары). Новая спека **полностью меняет философию продукта** и явно запрещает то, чем был SIDE QUEST: слово-бренд "SideQuest", геймификацию (XP/очки/стрики), язык продуктивности и self-improvement.

Это не инкремент над старым MVP, а пересборка контента/копирайта/бренда поверх того же стека (React + Vite + TypeScript). Старый код (`quests.json`, `drawQuest.ts`, компоненты) — хорошая техническая база, но контент и терминология будут переписаны.

Финальное название бренда — не "Tiny Plot", будет выбрано позже. Не строить визуальную идентичность вокруг этих слов.

## Идея продукта (кратко)

Приложение помогает взрослым сделать обычные дни более живыми, предлагая маленькие персонализированные реальные жизненные сценарии — не задачи, не чек-листы, не мотивационные советы. Каждый сценарий содержит элемент неожиданности/ограничения/ритуала/открытия и даёт что-то конкретное на память.

Не является: продуктивити-приложением, трекером привычек, self-improvement или mental-health продуктом, bucket-list или daily-challenge/геймифицированным приложением.

Эмоциональное обещание: *«Мне не нужна другая жизнь. Я хочу больше пережить из той, что уже есть»*.

## PHASE 1 — Анализ и дизайн (зафиксировано, ожидает подтверждения перед Phase 2)

### A. Понимание продукта

Продукт превращает свободный слот времени в конкретную, чуть театральную инструкцию, которая делает момент запоминающимся — без требования изменить образ жизни. Ядро — генератор (настроение + контекст → один сценарий) и архив памяти (Moments), который постфактум показывает, что обычное время дало реальную текстуру. Коллекции — открытие контента без генератора. Сезонность держит контент живым.

### B. Противоречия / UX-проблемы в спеке (и как они решены в IA/архитектуре ниже)

1. Существующий код прямо противоречит новой концепции (бренд/геймификация) — переписываем контент и копирайт, не архитектуру.
2. «Предельно просто» vs 5 последовательных вопросов контекста (время/компания/место/бюджет/энергия) — решение: один шаг «настроение», затем один свёрнутый лист контекста с предзаполненными дефолтами вместо 5 экранов.
3. Персонализация по причинам отказа vs явное требование не создавать пузырь предпочтений vs запрет свободной AI-генерации в MVP — решение: детерминированный взвешенный случайный выбор с мягким штрафом и полом веса (не ML), см. раздел F.
4. `season` не может быть одним enum-значением — Halloween/Autumn/Christmas/New Year пересекаются по датам. Решение: `season: Season[]`, текущая дата матчится на список активных сезонов, не одно значение.
5. Причина отказа «Not enough time» избыточна с уже заданным контекстом времени — логируется отдельно, идёт в контент-QA (проверка `duration_max`), а не в веса ранжирования вкуса.
6. Фото не могут храниться в `localStorage` (лимит ~5-10MB строк, только текст) — решение: IndexedDB (всё так же локально, без бэкенда/авторизации) для фото-блобов и остальных данных.
7. Риск перегруза выбора на главном экране (8 настроений + 13 коллекций на соседней вкладке) — решение: «Surprise me» визуально доминирует как основное действие, остальные 7 настроений — вторичный необязательный ряд.

### C. Информационная архитектура

```
Нижняя навигация: Today · Collections · Moments

Today (главная)
 └─ Настроение (8 чипов, «Surprise me» — визуально главный)
     └─ Шторка контекста (время · компания · место · бюджет · энергия — один лист с дефолтами)
         └─ Результат-сценарий (полноэкранная карточка)
             ├─ Let's do it → Активный сценарий (персистентный)
             │     └─ Флоу завершения → оценка → фото/заметка → Moment
             ├─ Not today → опциональная причина → повторный подбор
             └─ Save for later → в Moments/Saved

Collections → Детали коллекции (список + Choose for me) → Результат-сценарий

Moments → Saved (блок сверху) + Месячный архив (фотосетка, статистика месяца)

Settings — доступ с Today, не отдельная вкладка
```

### D. Основной пользовательский флоу

Today → тап настроения (или Surprise me) → шторка контекста с дефолтами → Make my plan → Результат-сценарий → (Let's do it → Активный сценарий → Mark as done → оценка → фото/заметка → Moment) | (Not today → причина → новый подбор) | (Save for later). Параллельно — свободный просмотр Collections в любой момент, тот же экран результата, но в рамках пула коллекции.

### E. Модель данных

```
Scenario {
  id, title, short_description, instructions,
  categories[], moods[], season[], company[],
  location: home|out|either,
  duration_min, duration_max,
  budget_level: free|low|medium|any,
  energy_level: very-low|normal|high,
  weather[], time_of_day[],
  requires_preparation: bool,
  indoor_outdoor: indoor|outdoor|both,
  novelty_score, social_level, romance_level, shareability_score: 1-5,
  safety_notes, collection_ids[], active, created_at
}

ScenarioEvent {           // append-only лог, основа и месячного, и будущего годового рекапа
  id, scenario_id,
  kind: viewed|accepted|rejected|saved|completed,
  rejection_reason?, rating?, occurred_at
}

Moment {
  id, scenario_id, scenario_title_snapshot,
  rating: loved|nice|not-for-me,
  photo_ref: IndexedDB-key|null, note,
  completed_at,
  tags_snapshot: { categories, novelty_score, social_level, romance_level, location }
}

UserContextSelection { time, company, location, budget, energy, updated_at }  // дефолты для шторки контекста
```

### F. Техническая архитектура

- Стек не меняется: React + Vite + TypeScript.
- **Без бэкенда** — всё локально, без авторизации. Бэкенд оправдан только синком между устройствами / реальным AI-ранжированием / шерингом по аккаунтам — не входит в MVP.
- **Хранение:** IndexedDB (`idb-keyval` или аналог) для всего, включая фото-блобы; `photo_ref` в Moment — ключ, не сам блоб.
- **Контент:** статический JSON, встроенный в бандл (как текущий `quests.json`), без сервера.
- **Алгоритм подбора:** жёсткий фильтр (сезон/настроение/контекст) → взвешенный случайный выбор среди прошедших → вес снижается (не до нуля, пол ~0.2) при совпадении атрибут-бакета с недавними (последние ~10) вкусовыми отказами → штраф недавно завершённым. Это точка, куда позже встанет LLM-переранжирование без изменения модели данных.
- PWA: манифест + базовый service worker, не критично для демо.

### G. Скоуп MVP

**Входит:** генератор (настроение+контекст+результат), Not today с причиной, Save for later, персистентный активный сценарий + флоу завершения + Moment, коллекции с Choose for me и прогрессом, месячный архив Moments, базовые настройки, взвешенный локальный подбор, ~160 кураторских сценариев (весь текст новый), шеринг-карточка 9:16 (без платформенных API), онбординг на 3 экрана.

**Откладывается:** UI годового рекапа (модель данных готова заранее), AI/LLM-генерация и ранжирование, аккаунты/синк/бэкенд, фильтр по погоде, нативная обёртка.

### H. Визуальная система

Тёплая нейтральная палитра (кремовый фон, один акцент, почти чёрный текст) — без градиентов и «розового self-care». Крупная дисплейная/serif типографика для заголовков + моно/гротеск для метаданных (сохраняем удачную пару Archivo Black + Space Mono из старого проекта, но без старого бренда/копирайта). Карточка сценария и карточка момента — главные поверхности. Сдержанная анимация, фото как основной визуальный материал в Moments, минимум иконок.

### I. Экраны MVP

1. Онбординг (3 экрана, skip, один раз)
2. Today (настроение + Surprise me)
3. Шторка контекста (модалка, дефолты + Make my plan)
4. Результат-сценарий (карточка, 3 действия)

8. Детали коллекции (список + Choose for me)

### J. Примеры сценариев (проверка контент-философии)

## PHASE 2 — Реализация

### Сделано

1. **Ребрендинг/очистка** — весь код SIDE QUEST (компоненты, `drawQuest.ts`, `storage.ts`, `quests.json`, геймифицированная терминология) удалён. Новый `package.json` name: `little-plans` (внутреннее, не финальный бренд).
2. **Модель данных** — `src/types.ts` (`Scenario`, `ScenarioEvent`, `Moment`, `UserContextSelection`), полностью по разделу E Phase 1.
3. **Хранение** — IndexedDB через `idb-keyval` (`src/lib/db.ts`): события, моменты, сохранённые сценарии, контекст, флаг онбординга, фото-блобы отдельным ключом. Без бэкенда, без авторизации.
4. **Сезонность** — `src/lib/season.ts`: `getActiveSeasons()` возвращает список активных сезонов на дату (пересечения Halloween/Autumn, Christmas/New Year и т.д. поддержаны).
5. **Контент** — `src/data/scenarios.json`: **70 кураторских сценариев** (не полные 160 из спеки — это осознанно урезанный, но качественный starter-набор, распределённый по 8 коллекциям: Feel Autumn, Better Date Nights, Evenings Better Than Scrolling, Zero Budget, Rainy Days, Make Something, Explore Your City, Childhood Again). Расширение до полного объёма — отдельная контент-сессия, не блокер для проверки гипотез MVP.
6. **Алгоритм подбора** — `src/lib/selectScenario.ts`: жёсткий фильтр (сезон/настроение/контекст) с прогрессивным ослаблением, чтобы никогда не быть без результата, + взвешенный случайный выбор со штрафами за недавние вкусовые отказы и недавние завершения (с полом веса, без AI).
7. **Все 11 экранов** реализованы: Onboarding, Today (настроение + активный сценарий), шторка контекста, Результат-сценарий, Активный сценарий, Complete-флоу (оценка + фото/заметка), Collections, Collection detail, Saved (внутри Moments), Moments/месячный архив, Settings.
8. Собрано и проверено: `npm run build` (`tsc -b` + `vite build`) чисто, `npm run lint` — 0 ошибок (1 безопасный warning про async-эффект загрузки фото), полный цикл прогнан headless-браузером (Playwright) — онбординг → выбор настроения → шторка контекста → результат → accept → active → complete (rating+note) → Moments показывает новый момент → Collections → детали коллекции. Скриншоты подтвердили визуал, консоль без ошибок.

### Обновление: локализация на русский + библиотека из 370 сценариев

По запросу пользователя:

- **Продукт переключён на русский язык**: весь UI-копирайт (`lib/options.ts`, `lib/collections.ts`, `lib/moments.ts`, все компоненты, `index.html`) переведён; `lang="ru"`.
- **Добавлено поле `tier: 'spark' | 'plan' | 'memory'`** в модель `Scenario` (`src/types.ts`) — метаданные, не показываются пользователю как отдельная кнопка/категория. Spark (5–60 мин, почти без подготовки), Plan (1–5 часов, «у нас был план»), Memory (5–20 мин, сохранить момент, чтобы не забылся) — алгоритм подбора сам приходит к нужному tier через существующие фильтры времени/энергии/бюджета/компании, без явного UI-переключателя, как и просил пользователь.
- **300 новых сценариев** (по 100 на Spark/Plan/Memory), присланных пользователем текстом, распарсены и размечены полными метаданными (categories, moods, season, company, location, duration, budget, energy, indoor/outdoor, scores) эвристически по ключевым словам и явным упоминаниям времени в тексте — плюс перевод/сохранение исходного русского текста как `title`/`instructions`. Старые 70 сценариев переведены на русский и получили `tier` (по длительности, с точечным переопределением на `memory` для явно рефлексивных: письма, чек, погодная заметка и т.п.).
- **Итого библиотека: 370 сценариев** (`src/data/scenarios.json`), объединение — не замена.
- Часть новых сценариев автоматически доразмечена в существующие 8 коллекций (по сезону/категории/компании), где это однозначно подходило — не силой, без искусственной подгонки всего массива под коллекции.
- **Добавлен фильтр по энергии** в `selectScenario.ts` (раньше энергия не влияла на подбор вообще — нашли и исправили при живом тестировании: запрос «совсем нет сил» отдавал сценарий про съёмку GIF за 3 видео). Теперь энергия — такой же порядковый мягкий фильтр, как бюджет.
- Прогнано headless-браузером на русском UI: онбординг → выбор настроения → шторка контекста → результат (проверены оба явных «Spark-формы» и «Plan-формы» контекста) → отказ с причиной → повторный подбор → принятие → активный план → завершение с оценкой/фото/заметкой → Moments → Collections. Консоль без ошибок. `npm run build` и `npm run lint` чистые.
