Ты выпускаешь изменения проекта «Маленькие планы» через GitHub. Прочитай раздел «Git и CI/CD» в `CLAUDE.md`.

## Порядок

1. `git status` и `git diff` — пойми, что именно меняется. Если в рабочей копии смешаны несвязанные изменения, спроси, что включать в PR, прежде чем коммитить.
2. Если текущая ветка `main` — создай ветку `feat/…`, `fix/…`, `chore/…` или `ci/…` с коротким именем по сути изменений.
3. Прогони `npm run lint` и `npm run build`. Если падает — остановись и сообщи ошибки, не пушь.
4. Добавляй файлы явно по путям (не `git add -A`). Никогда не добавляй `bot/.env`, `bot/data`, `dist`, `node_modules`.
5. Коммит: `<type>: <кратко>`; в конце сообщения — строки атрибуции, если они заданы в текущей сессии.
6. `git push -u origin <branch>`.
7. `gh pr create --base main` с заголовком как у коммита и телом по `.github/pull_request_template.md` (заполни разделы, отметь выполненные пункты чеклиста).
8. `gh pr checks --watch`. Если проверка упала — `gh run view <id> --log-failed`, коротко объясни причину и предложи исправление.

## Запреты

- Не пушь в `main` напрямую, не используй `--force`, не мёржь PR и не включай auto-merge без явной просьбы пользователя.
- Не меняй настройки репозитория (`gh api -X PUT/PATCH/POST …`) без явной просьбы.

## Отчёт

Ссылка на PR, статус каждой проверки CI, что осталось сделать.
